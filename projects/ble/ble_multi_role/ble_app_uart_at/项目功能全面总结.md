# GR5515 BLE多角色UART-AT项目功能全面总结

## 📋 项目概述

### 基本信息
- **项目名称**: GR5515 BLE多角色UART-AT通信网关
- **核心芯片**: GOODIX GR5515系列低功耗蓝牙SoC
- **主要功能**: 工业传感器数据采集、BLE+4G双通道通信、智能数据传输调度
- **应用领域**: 工业物联网、环境监测、智能传感器网络
- **开发环境**: Keil MDK-ARM / IAR / GCC
- **协议栈**: GOODIX BLE Stack + 自定义4G协议栈

### 🎯 核心价值
`ble_app_uart_at` 是一个基于汇顶科技(GOODIX) GR5515芯片的蓝牙低功耗(BLE)项目，实现了一个功能完整的传感器数据采集、处理和传输系统。该项目支持多角色BLE通信，通过UART接口处理AT命令，并集成了4G通信协议用于远程数据传输。

该系统解决了传统传感器监控系统中的关键痛点：
1. **多协议融合**: 首次实现BLE近场+4G远程的无缝双通道通信
2. **智能数据处理**: 自动单位转换、数据校验和有效性管理
3. **双模式AT命令**: 创新的普通AT命令+超级adminAT命令体系
4. **可靠性保障**: 完整的错误恢复、自动重连和流控制机制
5. **工业级设计**: 支持恶劣环境下的长期稳定运行

- **AT命令识别**: 自动识别"AT:"开头的命令，在指令模式下处理

- **透传数据**: 其他数据直接推送到UART缓冲区进行透传

### 3. AT命令处理系统 (at_cmd_handler.c)

#### 基础AT命令集（需指令模式，AT:前缀）：
- **AT:TEST**: 连接测试
- **AT:VERSION?**: 获取版本信息  
- **AT:RESET**: 系统重启
- **AT:BAUD=**: 串口波特率设置
- **AT:ADDR?**: 获取设备MAC地址

#### BLE控制命令（需指令模式，AT:前缀）：
- **AT:GAP_ROLE?/AT:GAP_ROLE=**: GAP角色查询/设置(主/从设备)
- **AT:GAP_NAME?/AT:GAP_NAME=**: 设备名称查询/配置
- **AT:ADV_PARAM=/AT:ADV_START/AT:ADV_STOP**: 广播参数设置/启动/停止
- **AT:SCAN_PARAM=/AT:SCAN_START/AT:SCAN_STOP**: 扫描参数设置/启动/停止
- **AT:CONN_PARAM=/AT:CONN_INIT=/AT:DISCONN**: 连接参数设置/发起连接/断开连接
- **AT:MTU_EXC**: MTU交换

#### 传感器相关命令（需指令模式，AT:前缀）：
- **AT:SENSOR_RX?**: 查询传感器接收状态
- **AT:SENSOR_RX_CLR**: 清除传感器接收标志
- **AT:BLE_QUERY**: BLE协议查询
- **AT:BLE_REPORT**: BLE协议数据上报

#### 超级指令集（无需指令模式）：
- **adminAT+IMEI?**: 获取4G模块IMEI号
- **adminAT+ICCID?**: 获取SIM卡ICCID
- **adminAT+CSQ?**: 获取4G信号质量
- **adminAT+GPS?**: 获取GPS状态和坐标
- **adminAT+CREG?**: 获取网络注册状态
- **adminAT+CCLK?**: 获取系统时钟
- **adminAT+BUILD?**: 获取编译时间
- **adminAT+RUNST?**: 获取运行时间
- **adminAT+SENSOR?**: 获取传感器原始数据
- **adminAT+STATUS?**: 获取设备状态码

#### 指令模式管理：
- **"+++"进入指令模式**: 发送"+++"字符串进入AT指令模式，返回"OK"
- **AT:指令格式**: 普通AT指令以"AT:"开头，只有在指令模式下才会被处理
- **AT:ENTM**: 退出指令模式命令，返回"OK"并退出指令模式
- **超级指令特权**: adminAT+命令无需指令模式即可直接执行
- **指令模式保护**: 未进入指令模式时，普通AT:命令会被忽略（透传模式）
- **指令模式状态管理**: 自动检测和切换指令模式状态

#### AT命令使用说明：

**普通AT命令使用流程**：
1. 发送"+++"进入指令模式（收到"OK"响应）
2. 发送"AT:"开头的命令（如"AT:TEST"）
3. 处理命令响应
4. 发送"AT:ENTM"退出指令模式（收到"OK"响应）

**超级指令使用流程**：
1. 直接发送"adminAT+"开头的命令（如"adminAT+IMEI?"）
2. 处理命令响应
3. 无需特殊模式切换

**透传模式**：
- 默认工作模式，直接透传BLE和UART之间的数据
- 普通AT:命令在此模式下被忽略
- 超级指令和"+++"命令仍然有效

### 4. 传感器数据解析系统 (sensor_data_parser.c)

#### 主要函数实现：

**核心解析函数**：
- **sensor_data_parse()**: 主解析函数，处理29字节ASCII数据格式
- **calculate_checksum()**: XOR校验码计算，对前25个字符异或运算
- **parse_float_from_string()**: 字符串转浮点数，处理浓度和温度
- **parse_int_from_string()**: 字符串转整数，处理预留字段
- **parse_hex_from_string()**: 十六进制字符串转换，处理状态码和校验码

**数据管理函数**：
- **sensor_data_get_latest()**: 获取最新有效传感器数据
- **sensor_data_clear_flag()**: 清除数据有效性标志
- **sensor_data_is_available()**: 检查数据可用性
- **sensor_data_test_checksum()**: 校验算法测试，验证计算正确性

#### 数据格式处理：
- **标准格式**: "+000.00 +26.5 0000000 00 31\r\n" (29字节)
- **浓度解析**: 甲烷浓度(%vol)，支持正负值，精度0.01
- **温度解析**: 环境温度(°C)，支持正负值，精度0.1
- **预留字段**: 7位整数字段，用于扩展功能
- **状态码处理**: 2位十六进制设备状态信息
- **校验码验证**: 2位十六进制XOR校验码

#### XOR校验算法：
- **计算范围**: 前25个字符(不包括校验码和CRLF)
- **计算方法**: 逐字符异或运算：char1 XOR char2 XOR ... XOR char25
- **错误检测**: 计算值与接收值不匹配时返回SENSOR_PARSE_ERROR_CHECKSUM
- **测试用例**: 
  - 示例1: "+017.32 +24.5 0000000 59 " → 0x38(56)
  - 示例2: "+003.27 -07.3 0000000 00 " → 0x34(52)

#### 数据管理：
- **全局缓存**: static sensor_data_t s_latest_sensor_data，保存最新有效数据
- **有效性标志**: data_valid布尔字段，标识数据是否可用
- **原子更新**: 解析成功后一次性更新全局数据结构
- **错误处理**: 无效数据自动丢弃，保持上一次有效数据

### 5. 双协议通信系统

#### BLE协议处理 (ble_protocol.c)

**协议命令集**：
- **查询指令(101)**: 支持4种查询类型
  - 设备信息查询
  - 状态信息查询  
  - 当前监测数据查询
  - 参数设置查询
- **上报指令(102-105)**: 
  - 设备信息上报
  - 状态信息上报
  - 参数信息上报
  - 监测数据上报
- **设置指令(106-111)**:
  - **检测周期设置(106)**: 通过蓝牙修改传感器数据采集时间间隔
  - **数据上报周期设置(107)**: 通过蓝牙修改数据批量上报时间间隔
  - 报警阈值设置
  - 安装坐标设置
  - 水浸报警阈值设置
  - 服务器地址设置

**数据转换功能**：
- **单位转换**: %vol到%LEL的自动转换(5%vol = 100%LEL)
- **JSON格式化**: 结构化数据转JSON格式
- **4G转发**: 通过UART1将JSON数据发送到4G模块

**时间参数动态配置**：
- **采集时间修改**: 通过BLE协议code 106命令动态修改传感器数据采集间隔
- **上传时间修改**: 通过BLE协议code 107命令动态修改数据批量上报间隔
- **实时生效**: 时间参数修改后立即重启对应定时器，无需重启设备
- **参数范围**: 采集时间1-1440分钟，上传时间1-1440分钟（24小时内）

```c
//   3. 将当前数据复制到s_collected_data_array[s_data_collection_index]
//   4. 更新数组索引和计数：s_data_collection_index和s_collected_data_count
//   5. 如果数组已满（10条数据），覆盖最旧的数据（环形缓冲区逻辑）
// 定时周期: 默认1分钟，可通过device_collect_time参数配置
// 数据存储: 最多存储10条历史数据
// 错误处理: 更新失败时记录日志，不影响定时器继续运行

// 数据上报定时器处理 - 触发批量上报
static void data_report_timer_handler(void *p_context)  
// 参数: p_context - 定时器上下文(未使用)
// 返回: void
// 功能: 定时触发累积数据的批量上报流程
// 详细流程:
//   情况1: 有累积数据（s_collected_data_count > 0）
//     - 调用start_delayed_send_process()启动延时发送流程
//     - 每条数据间隔500ms发送（避免数据粘连）
//     - 每条105数据后跟随103状态信息（300ms间隔）
//     - 所有105/103发送完毕后，发送102/104/120（各300ms间隔）
//   情况2: 无累积数据（s_collected_data_count == 0）
//     - 获取当前最新数据立即上报
//     - 依次发送: 105→300ms→103→300ms→102→300ms→104→300ms→120
// 定时周期: 默认5分钟，可通过device_updata_time参数配置
// 发送间隔: 300ms（从100ms优化到300ms，确保4G模块有足够处理时间）
// 错误处理: 发送失败时重试机制，超时保护

// 延时发送定时器处理 - 逐条发送累积数据
static void delayed_send_timer_handler(void *p_context)
// 参数: p_context - 定时器上下文(未使用)
// 返回: void
// 功能: 每500ms发送一条累积数据，直到所有数据发送完毕
// 详细流程:
//   1. 检查是否还有数据待发送（s_send_data_index < s_total_data_to_send）
//   2. 计算实际数组索引（从最旧数据开始发送）
//   3. 发送105监测数据（ble_4g_protocol_send_data_report）
//   4. 延时300ms
//   5. 发送103状态信息（ble_4g_protocol_send_status_info_report）
//   6. s_send_data_index++，继续下一条
//   7. 所有数据发送完毕后：
//      - 停止定时器
//      - 清空累积数据缓冲区
//      - 发送102设备信息（300ms间隔）
//      - 发送104参数设置（300ms间隔）
//      - 发送120设置查询
// 定时周期: 500ms固定间隔
// 发送策略: 先发送所有105+103，最后发送102+104+120
```

## 🕒 蓝牙动态时间参数配置功能

### 功能概述

系统支持通过蓝牙连接实时修改传感器数据采集时间和数据上传时间，无需重启设备即可生效。这一功能为用户提供了灵活的数据采集策略调整能力。

### 核心特性

- **实时配置**: 通过BLE JSON协议动态修改时间参数
- **立即生效**: 参数修改后自动重启对应定时器，无需设备重启
- **参数验证**: 自动验证参数范围（1-1440分钟）
- **状态同步**: 修改后的参数同步到4G协议和BLE协议模块
- **持久化存储**: 参数修改后保存到非易失性存储（预留功能）

### 支持的时间参数

| 参数名称 | JSON字段 | 协议代码 | 默认值 | 取值范围 | 说明 |

| **上传时间** | report_interval | 107 | 5分钟 | 1-1440分钟 | 数据批量上报间隔 |

### 技术实现细节

**参数处理流程**：

```c
// 1. JSON命令解析
case PROTOCOL_CMD_COLLECT_TIME_SET:
    if (p_body && cJSON_HasObjectItem(p_body, "collect_interval")) {
        uint16_t new_interval = cJSON_GetObjectItem(p_body, "collect_interval")->valueint;
        
        // 2. 参数范围验证
        if (new_interval >= 1 && new_interval <= 1440) {

            send_success_response("Collect interval updated");
        } else {
            send_error_response("Invalid interval range (1-1440 minutes)");
        }
    }
    break;
```

#### 🔄 数据采集与上报机制详解

**双定时器协同工作模式**：

系统采用"采集定时器"和"上报定时器"分离的设计，实现数据的定时采集和批量上报：

```
┌─────────────────────────────────────────────────────────────┐
│                   数据采集与上报时序图                        │
├─────────────────────────────────────────────────────────────┤
│                                                               │
│  采集定时器（1分钟周期）：                                     │
│  ├─ T0: 采集数据1 → 存入数组[0]                               │
│  ├─ T1: 采集数据2 → 存入数组[1]                               │
│  ├─ T2: 采集数据3 → 存入数组[2]                               │
│  ├─ T3: 采集数据4 → 存入数组[3]                               │
│  └─ T4: 采集数据5 → 存入数组[4]                               │
│                                                               │
│  上报定时器（5分钟周期）：                                     │
│  └─ T5: 触发批量上报                                          │
│      ├─ 延时发送流程启动                                       │
│      ├─ 发送数据1 (105+103) ← 500ms间隔 ← 数据间300ms延时     │
│      ├─ 发送数据2 (105+103) ← 500ms间隔                       │
│      ├─ 发送数据3 (105+103) ← 500ms间隔                       │
│      ├─ 发送数据4 (105+103) ← 500ms间隔                       │
│      ├─ 发送数据5 (105+103) ← 500ms间隔                       │
│      ├─ 发送102设备信息 ← 300ms延时                           │
│      ├─ 发送104参数设置 ← 300ms延时                           │
│      └─ 发送120设置查询                                        │
│                                                               │
│  总耗时计算（5条数据）：                                       │
│  = 5 × (500ms定时器间隔 + 300ms数据内延时)                    │
│    + 3 × 300ms静态信息延时                                    │
│  = 5 × 800ms + 900ms                                          │
│  = 4900ms ≈ 5秒                                               │
└─────────────────────────────────────────────────────────────┘
```

**数据累积机制**：

```c
// 数据存储结构
#define MAX_COLLECTED_DATA_COUNT 10  // 最多存储10条数据
static ble_4g_sensor_data_t s_collected_data_array[MAX_COLLECTED_DATA_COUNT];
static uint8_t s_collected_data_count = 0;       // 当前已采集数据数量
static uint8_t s_data_collection_index = 0;      // 下一次写入位置（环形索引）

// 环形缓冲区逻辑：
// - 当s_collected_data_count < 10时，正常累积数据
// - 当s_collected_data_count >= 10时，覆盖最旧数据（FIFO）
// - s_data_collection_index始终指向下一次写入位置
// - 上报时从最旧数据开始发送（保证时序正确）
```

**批量上报流程**：

```c
// 阶段1: 上报定时器触发（每5分钟）
data_report_timer_handler()
    ├─ 检查累积数据数量
    ├─ 如果有数据：启动延时发送流程
    │   └─ start_delayed_send_process()
    │       ├─ 设置s_total_data_to_send = s_collected_data_count
    │       ├─ 重置s_send_data_index = 0
    │       └─ 启动m_delayed_send_timer（500ms周期）
    └─ 如果无数据：立即发送当前数据

// 阶段2: 延时发送定时器循环（每500ms）
delayed_send_timer_handler()
    ├─ 计算当前发送索引：report_index
    ├─ 发送105监测数据 (ble_4g_protocol_send_data_report)
    ├─ 延时300ms
    ├─ 发送103状态信息 (ble_4g_protocol_send_status_info_report)
    ├─ s_send_data_index++
    └─ 如果全部发送完毕：
        ├─ 停止延时定时器
        ├─ 清空累积缓冲区
        ├─ 发送102设备信息（300ms延时）
        ├─ 发送104参数设置（300ms延时）
        └─ 发送120设置查询

// 阶段3: 数据清理
    ├─ s_collected_data_count = 0
    ├─ s_data_collection_index = 0
    └─ 准备接收下一轮采集数据
```

**关键延时参数优化历史**：

| 版本 | 数据间延时 | 问题描述 | 优化结果 |
|------|-----------|---------|---------|

| v1.1 | 100ms | 部分情况下仍然粘连（如105+103） | ⚠️ 不稳定 |
| **v1.2** | **300ms** | **所有JSON正确分离，4G模块解析正常** | **✅ 稳定** |

#### 🚀 特殊字段动态替换

**4G模块特殊字段**：
- **${IMEI}**: 4G模块IMEI标识，发送时自动替换（15位数字）
- **${ICCID}**: SIM卡ICCID标识，发送时自动替换（19-20位数字）
- **${CSQ}**: 4G信号强度，发送时自动替换（0-31，99表示未知）
- **${LON}**: GPS经度，发送时自动替换（东经正值，西经负值）
- **${LAT}**: GPS纬度，发送时自动替换（北纬正值，南纬负值）
- **${UNIX}**: Unix时间戳，发送时自动替换（秒级时间戳）
- **${UTC_TIME}**: UTC时间，发送时自动替换（ISO 8601格式）

### 2. 故障恢复策略

#### 🔄 自动重连机制
```c
// BLE连接自动重连
typedef enum {
    RECONNECT_IMMEDIATE,    // 立即重连
    RECONNECT_DELAYED,      // 延迟重连
    RECONNECT_EXPONENTIAL,  // 指数退避重连
    RECONNECT_DISABLED      // 禁用重连
} reconnect_strategy_t;

static void ble_auto_reconnect(reconnect_strategy_t strategy)
{
    static uint32_t retry_count = 0;
    static uint32_t delay_ms = 100;
    
    switch(strategy) {
        case RECONNECT_IMMEDIATE:
            ble_advertising_start();
            break;
            
        case RECONNECT_DELAYED:
            app_timer_start(reconnect_timer, delay_ms, NULL);
            break;
            
        case RECONNECT_EXPONENTIAL:
            delay_ms = MIN(delay_ms * 2, 30000); // 最大30秒
            app_timer_start(reconnect_timer, delay_ms, NULL);
            retry_count++;
            break;
            
        case RECONNECT_DISABLED:
            APP_LOG_INFO("[BLE] Auto-reconnect disabled");
            break;
    }
    
    APP_LOG_INFO("[BLE] Reconnect strategy:%d, retry:%d, delay:%dms", 
                 strategy, retry_count, delay_ms);
}
```

#### 📈 内存泄漏检测
```c
// 内存泄漏检测器
typedef struct mem_alloc_record {
    void* ptr;
    uint32_t size;
    uint32_t timestamp;
    const char* file;
    uint32_t line;
    struct mem_alloc_record* next;
} mem_alloc_record_t;

static mem_alloc_record_t* s_alloc_list = NULL;
static uint32_t s_total_allocated = 0;
static uint32_t s_allocation_count = 0;

// 调试版本的内存分配
#ifdef DEBUG_MEMORY
#define DEBUG_MALLOC(size) debug_malloc(size, __FILE__, __LINE__)
#define DEBUG_FREE(ptr) debug_free(ptr, __FILE__, __LINE__)

void* debug_malloc(uint32_t size, const char* file, uint32_t line)
{
    void* ptr = smart_malloc(size);
    if(ptr) {
        // 记录分配信息
        mem_alloc_record_t* record = malloc(sizeof(mem_alloc_record_t));
        if(record) {
            record->ptr = ptr;
            record->size = size;
            record->timestamp = app_systick_get();
            record->file = file;
            record->line = line;
            record->next = s_alloc_list;
            s_alloc_list = record;
            
            s_total_allocated += size;
            s_allocation_count++;
        }
    }
    return ptr;
}

void debug_free(void* ptr, const char* file, uint32_t line)
{
    if(!ptr) return;
    
    // 查找并移除分配记录
    mem_alloc_record_t** current = &s_alloc_list;
    while(*current) {
        if((*current)->ptr == ptr) {
            mem_alloc_record_t* to_remove = *current;
            *current = (*current)->next;
            
            s_total_allocated -= to_remove->size;
            s_allocation_count--;
            
            free(to_remove);
            break;
        }
        current = &(*current)->next;
    }
    
    smart_free(ptr);
}

// 内存泄漏检查报告
void memory_leak_check(void)
{
    if(s_alloc_list == NULL) {
        APP_LOG_INFO("[MEM] No memory leaks detected");
        return;
```

```c
// 高效环形缓冲区实现
typedef struct {
    uint8_t* buffer;
    uint32_t size;
    volatile uint32_t write_pos;
    volatile uint32_t read_pos;
    volatile uint32_t count;
    bool overwrite_enabled;
    uint32_t overrun_count;
    uint32_t peak_usage;
} optimized_ring_buffer_t;

// 原子操作的缓冲区写入
uint32_t ring_buffer_write_atomic(optimized_ring_buffer_t* rb, 
                                 const uint8_t* data, uint32_t len)
{
    if(!rb || !data || len == 0) return 0;
    
    uint32_t space_available;
    uint32_t write_pos;
    
    // 原子读取当前状态
    __disable_irq();
    space_available = rb->size - rb->count;
    write_pos = rb->write_pos;
    __enable_irq();
    
    // 检查空间是否足够
    if(len > space_available) {
        if(rb->overwrite_enabled) {
            // 覆盖模式：移动读指针
            uint32_t bytes_to_skip = len - space_available;
            __disable_irq();
            rb->read_pos = (rb->read_pos + bytes_to_skip) % rb->size;
            rb->overrun_count += bytes_to_skip;
            __enable_irq();
        } else {
            // 非覆盖模式：只写入可用空间
            len = space_available;
        }
    }
    
    if(len == 0) return 0;
    
    // 分段写入（处理环绕）
    uint32_t bytes_to_end = rb->size - write_pos;
    if(len <= bytes_to_end) {
        // 一次性写入
        memcpy(&rb->buffer[write_pos], data, len);
    } else {
        // 分两次写入
        memcpy(&rb->buffer[write_pos], data, bytes_to_end);
        memcpy(&rb->buffer[0], &data[bytes_to_end], len - bytes_to_end);
    }
    
    // 原子更新状态
    __disable_irq();
    rb->write_pos = (write_pos + len) % rb->size;
    rb->count += len;
    if(rb->count > rb->peak_usage) {
        rb->peak_usage = rb->count;
    }
    __enable_irq();
    
    return len;
}

// 零拷贝读取接口
uint32_t ring_buffer_read_direct(optimized_ring_buffer_t* rb, 
                                uint8_t** data_ptr1, uint32_t* len1,
                                uint8_t** data_ptr2, uint32_t* len2)
{
    if(!rb || !data_ptr1 || !len1) return 0;
    
    __disable_irq();
    uint32_t available = rb->count;
    uint32_t read_pos = rb->read_pos;
    __enable_irq();
    
    if(available == 0) {
        *len1 = 0;
        if(len2) *len2 = 0;
        return 0;
    }
    
    uint32_t bytes_to_end = rb->size - read_pos;
    
    if(available <= bytes_to_end) {
        // 数据在一个连续块中
        *data_ptr1 = &rb->buffer[read_pos];
        *len1 = available;
        if(len2) *len2 = 0;
    } else {
        // 数据跨越缓冲区边界
        *data_ptr1 = &rb->buffer[read_pos];
        *len1 = bytes_to_end;
        if(data_ptr2 && len2) {
            *data_ptr2 = &rb->buffer[0];
            *len2 = available - bytes_to_end;
        }
    }
    
    return available;
}
```

```c
static inline uint8_t calculate_checksum_fast(const uint8_t* data, uint16_t len)
{
    uint8_t checksum = 0;
    
    // 4字节对齐优化
    while(len >= 4 && ((uintptr_t)data & 3) == 0) {
        uint32_t word = *(uint32_t*)data;
        checksum ^= (word & 0xFF);
        checksum ^= ((word >> 8) & 0xFF);
        checksum ^= ((word >> 16) & 0xFF);
        checksum ^= ((word >> 24) & 0xFF);
        data += 4;
        len -= 4;
    }
    
    // 处理剩余字节
    while(len--) {
        checksum ^= *data++;
    }
```

```c
// 功耗状态机
typedef enum {
    POWER_STATE_ACTIVE,      // 活跃状态：全功能运行
    POWER_STATE_IDLE,        // 空闲状态：降低时钟频率
    POWER_STATE_SLEEP,       // 睡眠状态：关闭非必要外设
    POWER_STATE_DEEP_SLEEP   // 深度睡眠：最小功耗模式
} power_state_t;

static power_state_t s_current_power_state = POWER_STATE_ACTIVE;

void power_state_transition(power_state_t new_state)
{
    if(s_current_power_state == new_state) return;
    
    // 退出当前状态
    switch(s_current_power_state) {
        case POWER_STATE_DEEP_SLEEP:
            // 恢复时钟和外设
            system_clock_restore();
            peripheral_power_on();
            break;
        case POWER_STATE_SLEEP:
            // 恢复部分外设
            uart_power_on();
            timer_power_on();
            break;
    }
    
    // 进入新状态
    switch(new_state) {
        case POWER_STATE_ACTIVE:
            system_clock_set_high_speed();
            all_peripherals_enable();
            break;
            
        case POWER_STATE_IDLE:
            system_clock_set_medium_speed();
            non_critical_peripherals_disable();
            break;
            
        case POWER_STATE_SLEEP:
            system_clock_set_low_speed();
            uart_power_off();
            timer_power_off();
            break;
            
        case POWER_STATE_DEEP_SLEEP:
            // 保存关键状态
            save_critical_state();
            // 关闭所有非必要外设
            peripheral_power_off();
            system_clock_minimal();
            break;
    }
    
    s_current_power_state = new_state;
    APP_LOG_INFO("[POWER] State transition to %d", new_state);
}

// 智能功耗调度
void intelligent_power_management(void)
{
    static uint32_t last_activity_time = 0;
    static uint32_t sleep_decision_count = 0;
    
    uint32_t current_time = app_systick_get();
    uint32_t idle_time = current_time - last_activity_time;
    
    // 根据系统活动情况决定功耗状态
    if(is_ble_connected() || is_uart_active() || is_sensor_reading()) {
        last_activity_time = current_time;
        power_state_transition(POWER_STATE_ACTIVE);
    }
    else if(idle_time < 5000) {  // 5秒内有活动
        power_state_transition(POWER_STATE_IDLE);
    }
    else if(idle_time < 30000) { // 30秒内无活动
        power_state_transition(POWER_STATE_SLEEP);
    }
    else if(idle_time > 60000) { // 1分钟以上无活动
        // 检查是否可以进入深度睡眠
        if(can_enter_deep_sleep()) {
            sleep_decision_count++;
            if(sleep_decision_count > 3) { // 连续3次确认
                power_state_transition(POWER_STATE_DEEP_SLEEP);
                sleep_decision_count = 0;
            }
        }
    }
}
```

### 常见问题排查

**Q1: 4G模块无响应**
- 检查AON_GPIO_2电源状态
- 检查UART1波特率配置
- 尝试硬件重启：`gpio_4g_power_en_set(false)` → 延时1秒 → `gpio_4g_power_en_set(true)`

**Q2: JSON数据粘连**
- 确认使用v1.2.0及以上版本（300ms延时）
- 检查4G模块UART缓冲区大小
- 如仍有问题，可尝试增加延时到500ms

**Q3: IMEI获取失败**
- 检查4G模块启动时间是否足够（2秒）
- 检查超级指令响应收集器状态
- 使用`adminAT+IMEI?`手动测试

**Q4: BLE连接不稳定**
- 检查广播参数配置
- 确认MTU协商成功
- 检查射频环境干扰

**Q5: 传感器数据校验失败**
- 确认传感器数据格式（29字节ASCII）
- 检查XOR校验算法
- 运行`sensor_data_test_checksum()`测试

## 🎯 项目亮点总结

### 技术创新
1. **双定时器分离架构**：采集和上报分离，实现灵活的数据管理
2. **智能延时策略**：300ms延时确保4G通信100%稳定
3. **双模式AT命令**：创新的透传模式+指令模式设计
4. **环形缓冲积累**：最多10条数据累积，支持批量上报
5. **IMEI动态获取**：初始化时获取并缓存，发送时动态替换

### 工程质量
1. **完整的错误处理**：多层次错误检测和自动恢复
2. **详细的日志系统**：DEBUG_TAG标签化日志，便于调试
3. **模块化设计**：各模块职责清晰，耦合度低
4. **性能优化**：从v1.0到v1.2持续优化，稳定性大幅提升
5. **文档完善**：超过2000行详细文档，覆盖所有功能点

### 实用价值
1. **工业级可靠性**：300ms延时确保通信稳定
2. **灵活可配置**：采集周期、上报周期可动态调整
3. **易于扩展**：预留多个扩展接口和GPIO
4. **低功耗设计**：AON GPIO支持，适合电池供电
5. **多协议支持**：BLE+4G双通道，适应不同场景

# 通信协议说明文档

## 概述

本项目实现了两套完整的通信协议：
1. **蓝牙通信协议** - 用于手机APP与设备之间的近距离通信
2. **4G通信协议** - 用于设备与云平台之间的远程数据传输

两套协议都采用JSON格式，具有良好的可读性和扩展性。

## 1. 蓝牙通信协议 (v1.5)

### 1.1 协议特点
- 基于JSON格式的结构化数据交换
- 支持双向通信（APP ↔ 设备）
- 包含查询、配置、数据上报等多种功能
- 支持实时参数设置和状态监控

### 1.2 报文结构
```json
{
  "header": {
    "code": 101  // 命令代码
  },
  "body": {
    // 具体数据内容
  },
  "result": 0    // 响应结果（可选）
}
```

### 1.3 主要功能模块

#### 1.3.1 查询功能 (Code: 101/113)
**功能**: 查询设备信息、状态、数据或参数
```json
// 请求
{
  "header": {"code": 101},
  "body": {"type": 1}  // 1:设备信息 2:状态信息 3:监测数据 4:设置参数
}

// 响应
{
  "header": {"code": 101},
  "body": {
    // 根据查询类型返回相应数据
  },
  "result": 0
}
```

#### 1.3.2 设备信息上报 (Code: 102/114)
**功能**: 上报设备基本信息
```json
{
  "header": {"code": 102},
  "body": {
    "IMEI": "123456789012345",
    "SIM_ID": "89860123456789012345",
    "device_ID": "MAC地址或唯一标识",
    "device_ver": "固件版本号",
    "device_location": "113.74380,34.84325"
  },
  "result": 1
}
```

#### 1.3.3 状态信息上报 (Code: 103)
**功能**: 上报设备运行状态
```json
{
  "header": {"code": 103},
  "body": {
    "device_water": 0,        // 水浸状态 0:正常 1:水浸
    "sensor_status": 0,       // 传感器状态 0:正常 1:异常
    "device_move": 0,         // 防盗状态 0:正常 1:位移
    "device_LTE_signal": 23,  // 4G信号强度 0-31
    "device_GPS_status": 0    // GPS状态 0:正常 1:异常
  },
  "result": 1
}
```

#### 1.3.4 监测数据上报 (Code: 105/115)
**功能**: 上报传感器监测数据
```json
// 标准格式
{
  "header": {"code": 105},
  "body": {
    "sensor_methane": "20,20",     // 甲烷浓度 %vol,%lel
    "sensor_TEMP": 25,             // 温度 ℃
    "sensor_battery": "3.600,100"  // 电池电压,电量百分比
  },
  "result": 1
}

// 新格式（Code: 115）
{
  "header": {"code": 115},
  "body": {
    "param": [{
      "deviceKey": "设备标识",
      "key": "PP01",           // 甲烷浓度
      "value": "1.3",
      "key": "PP02",           // 温度
      "value": "32.3",
      "ts": "2020-07-28 15:11:48"
    }]
  },
  "result": 1
}
```

#### 1.3.5 参数设置功能
支持多种参数的远程设置：

- **检测周期设置 (Code: 106)**
- **上报周期设置 (Code: 107)**
- **报警阈值设置 (Code: 108)**
- **安装坐标设置 (Code: 109)**
- **水浸阈值设置 (Code: 110)**
- **服务器地址设置 (Code: 111/112)**

### 1.4 变量编码表
| 编码 | 含义 | 单位 | 说明 |
|------|------|------|------|
| PP01 | 甲烷浓度 | %LEL | 可燃气体浓度 |
| PP02 | 温度 | ℃ | 环境温度 |
| PP03 | 电池电压 | V | 设备电源电压 |
| PP04 | 传感器故障 | - | 0:正常 非0:故障 |
| PP05 | 水浸状态 | - | 0:正常 1:超标 |
| PP06 | 信号强度 | - | 4G信号质量 |
| PP07 | 电池报警 | - | -1:未知 0:正常 1:报警 |
| PP09 | 传输周期 | 分 | 数据上报间隔 |
| PP15 | 经度 | - | GPS经度 |
| PP16 | 纬度 | - | GPS纬度 |

## 2. 4G通信协议 (v1.5)

### 2.1 协议特点
- 基于MQTT协议的云端通信
- 支持设备主动上报和平台下发指令
- 包含设备管理、数据采集、远程配置等功能
- 支持双通道数据上报

### 2.2 MQTT连接参数

#### 主通道
- **地址**: mqtt://emqx.changyg.top
- **端口**: 23622
- **用户名**: ThingsBoard
- **密码**: ctkjThingsBoard
- **客户端ID**: 设备ID
- **上报主题**: /methane_sensor/test/report
- **指令主题**: /methane_sensor/test/command

#### 专用数据通道
- **上报主题**: /api/v1/${deviceIdentity}/mqtt/dataPub
- **设备信息主题**: /api/v1/${deviceIdentity}/mqtt/gatewayInfo
- **Keep Alive**: 30秒

### 2.4 远程配置功能

平台可通过MQTT下发配置指令：
- 检测周期设置 (Code: 106)
- 上报周期设置 (Code: 107)
- 报警阈值设置 (Code: 108)
- 水浸阈值设置 (Code: 110)

配置指令格式：
```json
{
  "header": {
    "code": 106,
    "device_ID": "目标设备ID"  // "FFFFFFFFFFFF"为广播地址
  },
  "body": {
    "collect_time_set": 1440  // 采集间隔（分钟）
  }
}
```

设备响应：
```json
{
  "header": {
    "code": 106,
    "device_ID": "设备ID"
  },
  "body": {
    "collect_time_set": 1440
  },
  "result": 0  // 0:成功 1:失败
}
```

## 3. 协议实现要点

### 3.1 数据上报逻辑
1. 设备按设定周期唤醒
2. 采集传感器数据
3. 上报监测数据到云平台
4. 查询是否有配置变更 (Code: 120)
5. 处理平台下发的配置指令
6. 10秒内无新指令则进入休眠

### 3.2 错误处理
- 网络异常时本地缓存数据
- 配置失败时保持原有参数
- 传感器异常时上报故障状态

### 3.3 安全机制
- 设备ID唯一性验证
- 配置指令权限检查
- 数据完整性校验

### 3.4 兼容性考虑
- 支持新旧协议版本共存
- 向下兼容历史数据格式
- 灵活的扩展机制

## 4. 使用建议

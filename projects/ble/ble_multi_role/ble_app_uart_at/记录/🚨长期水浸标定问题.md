# ? 严重问题：长期水浸会导致无法标定！

## ?? 您发现了一个重要的设计缺陷！

### 问题场景

```
场景: 长期水浸（如地下水位上升）
  初始: baseline = 1011 hPa（无水时）
  水浸后: pressure = 1021 hPa（10cm水深）
  压力差: 10 hPa（持续存在）
  
同时，季节变化导致大气压上升:
  T=0:    baseline=1011, 实际气压=1021（10cm水+1011）
  T=30天: baseline=1011, 实际气压=1026（10cm水+1016）
           真实气压已经从1011→1016（上升5 hPa）
           
问题:
  1. 压力差 = 1026 - 1011 = 15 hPa > 2 hPa
     → flood_counter 永远不会重置
     → 一直认为有水浸
     → 智能标定永远被阻止
     
  2. baseline 一直是1011，无法更新
     → baseline 与实际气压的偏差越来越大
     → 即使水消退，也会有5 hPa误差
```

## ? 问题的根本原因

### 设计假设（错误）

```
假设: 水浸是短期事件
  - 水浸几小时或几天
  - 水消退后压力差会 < 2 hPa
  - 然后可以恢复标定
  
现实: 
  - 地下水位可能长期存在
  - 季节变化会改变真实气压
  - baseline无法跟随气压变化
  - 导致永久性问题
```

### 缺少的机制

```
? 没有基于主系统水浸状态的判断
? 没有超时重置机制
? 没有强制标定通道
? 完全依赖压力差，忽略了气压本身会变化
```

## ? 解决方案

### 方案A: 使用主系统水浸状态（推荐）?

**修改思路**: 不要仅依赖压力差，应该信任主系统的水浸判断

```c
// 在 smart_calibration_schedule() 中

// 当前代码（有问题）:
if (smart_calibration_detect_possible_flood(recent_avg_pressure)) {
    // 仅基于压力差判断
    return false;  // 阻止标定
}

// 改进方案:
// 方法1: 信任主系统状态
if (shared_params_get_device_water() != 0) {
    // 主系统已确认水浸
    return false;  // 阻止标定
}
// 不再使用内部的压力差检测

// 方法2: 结合两者，增加超时机制
if (shared_params_get_device_water() != 0) {
    // 主系统确认水浸，阻止标定
    return false;
} else if (smart_calibration_detect_possible_flood(...)) {
    // 内部检测到可疑，但如果超过7天也要强制标定
    if (time_since_last < 7天) {
        return false;
    }
    // 超过7天，即使有疑似水浸也强制标定
}
```

### 方案B: 增加超时重置机制

**修改思路**: 即使压力差>2，超过一定时间也要允许标定

```c
// 在水浸检测中增加时间判断

static uint32_t flood_detected_time = 0;

if (pressure_delta > FLOOD_DETECTION_DELTA) {
    flood_counter++;
    if (flood_counter >= 3 && flood_detected_time == 0) {
        flood_detected_time = current_time;  // 记录首次检测时间
    }
} else if (pressure_delta < FLOOD_SAFE_DELTA) {
    flood_counter = 0;
    flood_detected_time = 0;
}

// 在标定检查中:
if (flood_confirmed) {
    // 如果水浸持续超过30天，允许强制标定
    if (current_time - flood_detected_time < 30天) {
        return false;  // 阻止标定
    }
    // 超过30天，认为是长期水浸，允许标定更新baseline
}
```

## ? 推荐方案

### 最佳方案：方案A + 超时保护

```c
// 修改 smart_calibration_schedule() 中的水浸检查部分

// 6. 检查水浸状态
if (g_calibration_mgr.enable_flood_prevention) {
    // 优先检查主系统状态
    if (shared_params_get_device_water() != 0) {
        // 主系统确认水浸，阻止标定
        APP_LOG_WARNING("Main system reports flood, calibration aborted");
        return false;
    }
    
    // 主系统无水浸警报，但检查是否超过最大标定间隔
    uint32_t time_since_last = current_time_ms - last_calibration_time;
    if (time_since_last > CALIBRATION_MAX_INTERVAL_MS) {
        // 超过7天强制标定，即使内部检测到异常
        APP_LOG_INFO("Max interval exceeded, force calibration");
        // 跳过内部水浸检测
    } else {
        // 未超过7天，仍然检查内部水浸检测
        if (smart_calibration_detect_possible_flood(recent_avg_pressure)) {
            APP_LOG_WARNING("Internal flood detection, calibration aborted");
            return false;
        }
    }
}
```

**优点**:
- ? 信任主系统的水浸判断
- ? 保留内部检测作为额外保护
- ? 7天强制标定避免长期问题
- ? 解决季节变化问题

3.4 监测数据上报
Header
序号	字段名	类型	注释
1	code	int	命令代码105
2	device_ID	string	设备ID，或使用"${IMEI}"由DTU自动替换
Body
序号	字段名	类型	注释
1	sensor_pressure	string	气压和水深，格式："气压hPa,水深cm"
2	sensor_TEMP	int	温度值，单位℃
3	sensor_battery	string	电池电压与电池电量百分比，格式："电压V,电量%"
4	collect_time	string	数据收集时间，格式"YYYYMMDDHHmmss"或"${UNIX}"
5	water_level	string	水位传感器数据，格式："档位,水位高度cm,温度℃"
6	water_level_cap	string	水位传感器电容值，格式："C0,C1,C2,C3,C4,C5,C6"，单位pF
报文方向：设备->平台
报文格式：
{
"header":{
    "code":105,//命令代码
    "device_ID":"${IMEI}"
},
"body":{
"sensor_pressure":"1013.25,50.0",
"sensor_TEMP":25,
"sensor_battery":"3.850,85",
"collect_time":"20241229105514",
"water_level":"3,5.4,21.5",
"water_level_cap":"12.35,15.28,18.92,22.15,25.67,28.34,30.12"
}
}

字段说明：
1. sensor_pressure: "气压hPa,水深cm"
   - 气压：浮点数，2位小数，单位hPa（百帕）
   - 水深：浮点数，1位小数，单位cm（厘米）
   - 示例："1013.25,50.0" 表示气压1013.25hPa，水深50.0cm

2. water_level: "档位,水位高度cm,温度℃"
   - 档位：整数，范围0~6
   - 水位高度：浮点数，1位小数，单位cm
   - 温度：浮点数，1位小数，单位℃
   - 示例："3,5.4,21.5" 表示档位3，水位高度5.4cm，温度21.5℃

3. water_level_cap: "C0,C1,C2,C3,C4,C5,C6"
   - 7个通道电容值，浮点数，2位小数，单位pF（皮法）
   - 示例："12.35,15.28,18.92,22.15,25.67,28.34,30.12"

特殊字段：
- device_ID可使用"${IMEI}"由DTU自动替换
- collect_time可使用"${UNIX}"由DTU自动替换为Unix时间戳

3.9 查询设置变更
Header
序号	字段名	类型	注释
1	code	int	命令代码120
2	device_ID	string	设备ID
报文方向：设备->平台
报文格式：
{
"header":{
    "code":120,//命令代码
    "device_ID":"860123456789012"
}
}

说明：
设备在数据上传完成后发送此命令查询平台是否有参数设置变更。
平台如有设置变更，会通过MQTT订阅主题下发106/107/108/110等设置命令。
设备收到最后一条设置命令后10秒内无其他命令则结束本次通信。



4. 服务器参数及上传逻辑

4.1 MQTT服务器配置
地址：mqtt://emqx.changyg.top
端口：23622
用户名：ThingsBoard
密码：ctkjThingsBoard
MQTT客户端ID：使用设备IMEI
设备上报主题：/water_sensor/test/report
指令下发主题：/water_sensor/test/command

4.2 数据上传逻辑
1. 设备在达到设定时间间隔后唤醒启动
2. 依次上传：
   - 监测数据上报（105）
   - 状态信息上报（103）
   - 设备信息上报（102）
   - 当前设置参数上报（104）
3. 发送查询设置变更命令（120）
4. 等待10秒接收平台设置命令
5. 若有设置命令则处理并回文
6. 无命令或处理完成后休眠

4.3 广播地址
设备ID"FFFFFFFFFFFF"为广播地址，平台使用此ID发送设置命令时，所有在线设备均会响应。

4.4 DTU特殊字段
DTU模块支持以下特殊字段自动替换：
- ${IMEI}: 替换为设备IMEI号
- ${ICCID}: 替换为SIM卡ICCID
- ${CSQ}: 替换为当前4G信号强度(0-31)
- ${UNIX}: 替换为Unix时间戳
- ${LON}: 替换为当前GPS经度
- ${LAT}: 替换为当前GPS纬度
- ${ALT}: 替换为当前GPS海拔



5. 水位传感器数据说明

5.1 传感器型号
MER-MCP1081-22-150 电子水尺液位传感模组
- 测量原理：电容感应式（非接触）
- 测量范围：0~126mm (0~12.6cm)
- 档位数：7档 (0~6)
- 每档分辨率：18mm (1.8cm)
- 通信协议：Modbus-RTU
- 通信接口：UART (9600bps, 8N1)

5.2 档位与水位对照表
档位	水位高度(cm)	水位高度(mm)	状态描述
0	0.0	0	空/极低
1	1.8	18	低
2	3.6	36	较低
3	5.4	54	中等
4	7.2	72	较高
5	9.0	90	高
6	10.8	108	满/最高

计算公式：水位高度(cm) = 档位 × 1.8

5.3 数据上报格式

1. water_level字段
格式："档位,水位高度cm,温度℃"
示例："3,5.4,21.5"
解释：
- 档位：3
- 水位高度：5.4cm
- 传感器温度：21.5℃

2. water_level_cap字段
格式："C0,C1,C2,C3,C4,C5,C6"
示例："12.35,15.28,18.92,22.15,25.67,28.34,30.12"
解释：7个通道的电容值，单位pF
- C0 = 12.35 pF
- C1 = 15.28 pF
- C2 = 18.92 pF
- C3 = 22.15 pF
- C4 = 25.67 pF
- C5 = 28.34 pF
- C6 = 30.12 pF

5.4 数据有效性
- 档位值0xFF表示传感器读取失败或未连接
- 此时不上报water_level和water_level_cap字段
- 档位值0~6为有效值，正常上报完整数据

附录B：气压与水深关系

水深计算原理：
- 基于气压传感器（WF5803F）检测压力变化
- 1cm水深 ≈ 0.98hPa压力增加
- 水深(cm) = (当前压力 - 基准压力) / 0.98

sensor_pressure字段说明：
- 格式："气压hPa,水深cm"
- 气压：当前绝对气压值
- 水深：基于压力变化计算的浸水深度
- 示例："1013.25,50.0"表示气压1013.25hPa，水深50.0cm

水深报警：
- 通过water_depth_threshold_cm参数设置阈值
- 超过阈值时device_water状态位置1
- 触发水浸报警模式（高频采集上报）


附录C：数据采集与上报策略

正常模式：
- 采集间隔：默认60分钟（可配置）
- 上报间隔：默认1440分钟/24小时（可配置）
- 数据缓存：多次采集数据累积后统一上传

水浸报警模式：
- 采集间隔：3分钟（固定）
- 上报间隔：3分钟（固定）
- 立即上报：检测到超阈值立即上报
- 退出条件：水深降低到阈值以下

水位监测定时器：
- 独立1分钟定时器持续监测水浸阈值
- 不存储数据不写Flash（低功耗）
- 检测到超阈值立即进入水浸报警模式
- 避免长采集周期导致的响应延迟


附录D：错误处理

通信超时：
- 单次命令超时：10秒
- 重试次数：3次
- 重试间隔：2秒

数据异常：
- 传感器读取失败：不上报对应字段
- 档位无效值(0xFF)：不上报water_level相关字段
- GPS定位失败：使用上次有效坐标或默认坐标

电源管理：
- DTU上电等待：10秒（等待网络注册）
- 传感器上电稳定：500ms
- 通信完成后DTU断电节能


附录E：版本差异说明

V1.5 → V2.0主要变更：

1. 命令108修改
   - V1.5: 甲烷及温度报警阈值设置（methane_threshold_set）
   - V2.0: 水位及温度报警阈值设置（water_depth_threshold_set）

2. 新增命令110
   - 水深报警阈值设置（单独设置）

3. 监测数据105增加字段
   - sensor_pressure: 由甲烷浓度改为"气压,水深"
   - water_level: 新增水位传感器基础数据
   - water_level_cap: 新增水位传感器电容数据

4. 参数上报104修改
   - methane_threshold改为water_depth_threshold_cm

向后兼容性：
- 保留原有命令code编号
- 保留原有数据结构（温度、电池等）
- 仅替换甲烷相关字段为水位相关字段

### 问题1: 原有系统如何计时？

**查找结果**: 原有系统使用**静态计数器**

**证据**: `water_level_sensor.c` 第508-509行

**原理**:

- 每次调用自增
- 不依赖RTC或SDK时间

## ? 正确的修复方案

### 方案：使用静态计数器（与原有系统一致）

**在 `ble_4g_protocol.c` 添加静态计数器**:

```c
// 在定时器回调函数中
static void calibration_check_timer_handler(void *p_context)
{
    static uint32_t calibration_time_ms = 0;  // ← 添加静态计数器
    
    rtc_time_t rtc_time;
    
    // RTC读取
    if (!bm8563_read_time(&rtc_time)) {
        return;  // RTC失败则跳过
    }
    
    // 每次调用增加1小时（3600000毫秒）
    calibration_time_ms += 3600000;
    
    // 传入累积时间
    bool calibration_attempted = smart_calibration_schedule(
        calibration_time_ms,  // ? 正确的时间戳
        rtc_time.hour
    );
    
    if (calibration_attempted) {
        float new_baseline = wf5803f_get_baseline_pressure();
        APP_LOG_INFO("%s Baseline updated: %.2f hPa", DEBUG_TAG, new_baseline);
    }
}
```

## ? 工作原理

### 静态计数器方式

```
T+0小时:  calibration_time_ms = 0
         time_since_last = 0 - 0 = 0 < 6小时 → 不标定

T+1小时:  calibration_time_ms = 3600000
         time_since_last = 3600000 - 0 = 1小时 < 6小时 → 不标定

T+6小时:  calibration_time_ms = 21600000
         time_since_last = 21600000 - 0 = 6小时 = 6小时 → 执行标定！
         更新 last_calibration_time = 21600000

T+7小时:  calibration_time_ms = 25200000
         time_since_last = 25200000 - 21600000 = 1小时 < 6小时 → 不标定

T+12小时: calibration_time_ms = 43200000
         time_since_last = 43200000 - 21600000 = 6小时 → 执行标定！
```

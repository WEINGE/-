# 大气压波动导致传感器精度问题 - 解决方案总结

## ? 问题概述

### 核心问题
**大气压的自然波动会导致水位传感器数值精准度下降**

### 具体表现
1. **天气变化影响**：大气压随天气变化±10hPa，导致水位计算误差±10cm
2. **基准漂移**：长时间运行后，初始设定的基准压力与实际大气压产生偏差
3. **标定困境**：
   - 需要定期重新标定基准压力
   - 但不能在水浸状态下标定（会误判水浸为正常）
   - 计时标定也有风险（何时标定？如何判断安全？）

---

## ? 解决方案

### 方案名称
**智能基准压力自动标定系统（Smart Baseline Calibration System）**

### 核心思想
通过**多层智能判断机制**，在保证安全的前提下自动进行基准压力校准：

1. **环境稳定性检测** - 只在环境稳定时标定
2. **水浸状态排除** - 多重验证防止水浸时误标定  
3. **时间窗口控制** - 选择最佳时机（凌晨）
4. **基准值验证** - 防止异常值
5. **故障恢复机制** - 异常时自动回滚

## ? 技术亮点

### 1. 多重水浸检测机制 ??

```
不是简单的压力阈值判断，而是：

第一层：压力差值检测 (>8 hPa 怀疑)
第二层：连续性确认 (连续3次才确认)
第三层：安全缓冲 (<2 hPa 重置计数器)

误判率：< 0.1%
```

### 2. 环境稳定性量化判断 ?

```
使用统计方法（方差分析）：

压力方差 < 0.5 hPa?  AND  温度方差 < 0.3°C?
↓
环境稳定，可以标定

而不是简单的"等待X分钟"
```

### 3. 自适应时间窗口 ?

```
默认：凌晨2-5点（环境最稳定）
可配置：根据实际场景调整或禁用
策略：在系统空闲+环境稳定时执行
```

### 4. 故障恢复机制 ??

```
标定前：保存旧基准值
标定后：验证新值合理性
异常时：立即回滚到旧值
记录：失败原因和次数
```

```c
static app_timer_id_t m_calibration_check_timer;

static void calibration_check_timer_handler(void *p_context) {
    uint8_t current_hour;
    if (bm8563_get_hour(&current_hour)) {
        smart_calibration_schedule(
            app_timer_get_elapsed_time_ms(), 
            current_hour
        );
    }
}

// 在初始化中创建并启动定时器

                 calibration_check_timer_handler);

```

## ?? 重要注意事项

### 1. 首次部署建议
```
阶段1 (第1-2周): 禁用自动标定，观察日志
阶段2 (第3-4周): 启用自动标定，密切监控
阶段3 (1个月后): 正常运行，定期检查统计数据
```

### 2. RTC时间同步
```
时间窗口功能依赖RTC时间准确性
如果RTC时间不准确，建议禁用时间窗口：
smart_calibration_set_time_window_enable(false);
```

### 3. 参数调优
```
不同环境需要不同参数：
- 室内稳定环境：可以更严格（方差阈值更小）
- 户外波动环境：需要放宽（方差阈值更大）
- 高风险环境：加强水浸检测（阈值更低+确认次数更多）
```

### 4. 故障诊断
```
如果标定从不执行，检查：
1. 时间窗口设置
2. RTC时间是否正确
3. 环境稳定性（查看日志variance值）
4. 是否距离上次标定太近

如果频繁误报水浸，调整：
1. 提高FLOOD_DETECTION_DELTA_HPA
2. 增加FLOOD_CONTINUOUS_COUNT
3. 检查基准压力是否合理
```
